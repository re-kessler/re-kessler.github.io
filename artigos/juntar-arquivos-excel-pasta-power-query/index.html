Como juntar vários arquivos do Excel de uma pasta no Power Query

13 de novembro de 2026 · Renan Kessler

Três filiais mandam uma planilha de vendas por mês. Cada arquivo tem uma aba chamada Vendas com as mesmas colunas: Data, Item e Valor. Você guarda os arquivos numa pasta só e quer uma tabela que junte tudo e continue certa quando chegar o arquivo do mês seguinte.

O Power Query faz isso com uma consulta que lista a pasta, abre cada arquivo e empilha o conteúdo. O código abaixo foi executado no Excel 365 com três filiais de teste (30 linhas no total).

A consulta completa

Crie uma consulta em branco (Dados → Obter Dados → De Outras Fontes → Consulta em Branco), abra Página Inicial → Editor Avançado e cole:

let
    Pasta = "C:\Relatorios\Filiais\",
    Arquivos = Folder.Files(Pasta),
    DaPasta = Table.SelectRows(Arquivos, each [Folder Path] = Pasta),
    SoExcel = Table.SelectRows(
        DaPasta,
        each Text.Lower([Extension]) = ".xlsx" and not Text.StartsWith([Name], "~$")
    ),
    Lidos = Table.AddColumn(
        SoExcel,
        "Dados",
        each Excel.Workbook([Content], true){[Item = "Vendas", Kind = "Sheet"]}[Data]
    ),
    Mantidas = Table.SelectColumns(Lidos, {"Name", "Dados"}),
    Expandido = Table.ExpandTableColumn(Mantidas, "Dados", {"Data", "Item", "Valor"}),
    Tipado = Table.TransformColumnTypes(Expandido, {{"Data", type date}, {"Valor", type number}})
in
    Tipado

Troque o caminho da primeira linha pelo da sua pasta e termine-o com uma barra invertida (o motivo está no fim do artigo). O resultado é uma tabela com quatro colunas: Name (o arquivo de origem), Data, Item e Valor. A coluna Name não custa nada e ajuda muito. Quando um total parecer estranho, ela mostra de qual filial veio cada linha.

O que cada etapa faz

Folder.Files lista a pasta, e cada linha da tabela que ela devolve é um arquivo. O artigo usa quatro colunas: Name, Extension, Folder Path e Content, que carrega o arquivo inteiro como valor binário.

Excel.Workbook recebe esse binário e devolve uma tabela com o que existe dentro da pasta de trabalho: abas, tabelas e intervalos nomeados. O segundo argumento, true, promove a primeira linha de cada aba a cabeçalho. A chave {[Item = "Vendas", Kind = "Sheet"]} escolhe a aba pelo nome, e [Data] pega o conteúdo dela. Por isso Table.AddColumn cria uma coluna em que cada célula já contém uma tabela inteira.

Table.ExpandTableColumn abre essa coluna e empilha as tabelas, repetindo o nome do arquivo em cada linha. É o passo que faz o trabalho de juntar.

As duas linhas que parecem sobrar

DaPasta e o teste de ~$ existem porque, na pasta de teste, a lista de arquivos tinha cinco itens e só três eram filiais.

O primeiro intruso é um arquivo de trava. Quando alguém está com Filial_Sul.xlsx aberto, o Excel cria ao lado dele um ~$Filial_Sul.xlsx. Esse arquivo não é uma planilha. Sem o filtro, Excel.Workbook tenta abri-lo e a atualização falha com DataFormat.Error: "Não foi possível carregar esse arquivo do Excel porque não conseguimos entender seu formato." No teste usei um arquivo de 165 bytes com esse nome, sem abrir o Excel de verdade. O erro é o de qualquer arquivo que não seja uma planilha.

O segundo intruso é uma subpasta. Folder.Files lista também os arquivos das subpastas, segundo a documentação da Microsoft. Quem guarda uma cópia antiga em Filiais\Antigos\Filial_Norte.xlsx passa a ter o mesmo nome duas vezes na lista. Sem DaPasta, a tabela do teste saiu com 40 linhas em vez de 30, e a filial Norte apareceu em dobro, sem nenhum aviso. O filtro compara Folder Path com a pasta pedida e deixa de fora tudo o que estiver mais fundo.

Onde isso quebra

A barra invertida do fim do caminho não é enfeite. Folder.Files aceita a pasta sem ela, mas Folder Path sempre vem com a barra. Com Pasta = "C:\Relatorios\Filiais", a comparação de DaPasta não bate com nenhuma linha. A tabela final sai vazia, sem mensagem de erro.

A consulta também assume que toda planilha tem uma aba Vendas e as três colunas. Uma filial que renomeie a aba para Janeiro derruba a atualização com Expression.Error: A chave não correspondia a nenhuma linha na tabela. A mensagem não cita o arquivo nem a aba, e você só descobre qual foi olhando a coluna Name da lista. Se ela renomear uma coluna, o erro é outro, e o artigo sobre "a coluna da tabela não foi encontrada" mostra como fazer a consulta dizer qual arquivo falhou.

O filtro de extensão deixa de fora .xlsm e .xls. Se a sua pasta mistura formatos, acrescente a extensão à condição da etapa SoExcel e confira que o arquivo novo abre com Excel.Workbook antes de confiar no total.
